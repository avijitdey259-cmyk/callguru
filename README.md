# PiCall

Bilingual (English & Bengali) live pay-per-minute expert consultation, social community and creator marketplace — React 18 + Vite + TypeScript + Tailwind, with a small Express backend in `server/`.

> Formerly branded "CallGuru" — renamed to **PiCall** (in-app branding only; GitHub repo and backend are unchanged). Live site: https://picallbd.web.app (Firebase Hosting; Netlify dropped 2026-11-19). The old default site https://picall-76185.web.app still exists.
>
> **PWA:** PiCall is installable — `public/manifest.webmanifest` + `public/sw.js` (offline app shell) + an "📲 অ্যাপ ইন্সটল করুন" button in the header, Menu page and landing page. The button uses `beforeinstallprompt` when available, otherwise shows per-browser steps (Android Chrome / iPhone Safari). Real-phone install test is still the user's to do.

**Live demo:** frontend works standalone in demo/local mode (localStorage seed data, no live backend required). The live server (WebSocket signalling + WebRTC, STUN + free shared TURN for testing) is self-hosted in `server/` — see "Dating Live" below. Real Firebase Auth, SMS gateway, a paid TURN server and payment gateways still need real project credentials before real users.

## Key rules (v6)

- **Calls are PREPAID** — top-up first, no balance = no call. Live prepaid meter, auto-cut when balance runs out.
- **Chat is FREE** everywhere. Calls are NOT free.
- **Free minutes: NOT 2 minutes free.** Only the first call's first 1 minute free, for first users / first friend.
- Friend calls flat **৳10/min**; expert calls at the expert's own rate.
- Wallet packs **৳100–৳1,000**; bKash / Nagad / Rocket / USDT / Binance Pay top-up (Bank removed 2026-11-20 — it did not work).
- Chat blocks phone numbers, WhatsApp/Facebook/Telegram links and emails (attempts logged, repeat attempts escalate).
- Chat friends: 5 friends (রিমা, শাকিল, ফাহিম, মিম, আশা) appear in the Friends list and Chat list like normal users and reply like people with emotion, each with their own voice (funny, caring, helpful, music lover, dreamy), with a typing indicator ("লিখছে…") and a 1–3 second reply delay. Replies come from a local reply engine in the frontend (`src/buddies.ts`) — keyword-aware Bengali replies, varied per intent, never the same reply twice in a row for the same input; no external AI API or API key. Conversations persist in localStorage like normal chats, and a friend's 💬 চ্যাট button opens that friend's chat directly. They can be unfriended like any friend (they do not come back). They appear ONLY in Friends/Chat — never in Dating.
- Dating is **18+ only**, 30 free likes/day, Premium ৳99/month, Boost ~০.১ π, Super Like ০.১৫ π.
- Live TV: Bangladeshi channels only, in-app HLS player + official source link. No external video links.
- Call recordings are **admin-only, for appeals** (30-day retention). Call screen shows only a small red dot — no "Recording" text.
- **Camera switch:** in a call, the 🔄 "ক্যামেরা: সামনে/পেছনে" button switches front ↔ back camera (facingMode `user`/`environment`, exact first, plain fallback). Only the video track is restarted — audio, call timer and billing keep running. Front camera self-view is mirrored, back camera is not. If the device has only 1 camera, the button is disabled with a note. The pre-call screen also lets the user pick front/back before starting.
- **Dating video call (prepaid):** after a match only, a "📹 ভিডিও কল করুন (প্রিপেইড)" button appears on the match card and on the matched profile's card → `/call/dating/<profile-id>`. Rate is admin-adjustable from Admin → Revenue ("ডেটিং কল রেট (৳/মিনিট)", min ৳1, whole taka, default ৳10, saved to localStorage) — the pre-call screen, match card and profile button all show the current saved rate. **Only the caller pays**, no free minute (the global first-1-minute-free does not apply and is not consumed by a dating call), prepaid gate + auto-cut on empty balance like other calls. History records it as type `Dating`. Recording is the same as other calls: small red dot only, admin-only for appeals, no user record button. Friend calls stay at the flat ৳10/min FRIEND_RATE — only the dating rate is admin-adjustable.
- **Dating KYC (one-time, mandatory, admin-reviewed):** all of Dating is gated behind a one-time live KYC (`KycPage` in `src/pages.tsx`). Step 1 — পরিচয়: full name, date of birth (age must be 18+), ID type (NID / Passport / Birth Certificate), ID number — **the FULL NID number is stored from step 1** (`kycInfo.idNumber` in localStorage, alongside `idLast4` for short display) so the admin can match it; NID must be 10 or 17 digits, Passport/Birth Certificate at least 6 characters. **Warning: a full NID is sensitive personal data — in real production it must NOT be stored in plain text; encrypt it and use a verified KYC service.** Older submissions that only have the last 4 show "পুরো নম্বর সংরক্ষিত নেই (আগের জমা)" and the user can re-submit to provide the full number. Step 2 — লাইভ সেলফি: live front-camera preview, capture a selfie (downscaled to max 320px, JPEG 0.7) **plus a ~3-second live video clip** (MediaRecorder, 200 kbps; file-upload fallback has no video). Submit → status `pending`; **only an admin approval unlocks Dating** (`kycStatus: none | pending | approved | rejected` in `src/store.tsx`, `kycVerified` is derived = approved). While pending, Dating shows "⏳ KYC পর্যালোচনাধীন" and nothing else; if rejected, the admin's reason is shown with a "আবার KYC জমা দিন" button (re-submission resets to pending). **Admin review — Admin panel → "KYC যাচাই" tab:** shows the submitted name, DOB + age, ID type, **the FULL ID number** (or "পুরো নম্বর সংরক্ষিত নেই (আগের জমা)" for older submissions), ID last 4, submitted date, the selfie photo AND a playable live-video clip side by side so the admin can match the person, plus "✅ অনুমোদন করুন" / "❌ বাতিল করুন" (rejection needs a short reason, stored as `kycRejectReason`). Selfie, video and the full ID number are kept **only for admin verification** — not shared with other users, not uploaded anywhere (demo: localStorage on this device only); if video recording/storage fails, the selfie alone is used and the admin screen says the video could not be kept. **Admin live monitoring — same KYC tab, "🔴 চলমান লাইভ দেখুন" section:** lists currently live rooms from `GET /api/live` (host, viewer count, started time) with a "👁️ দেখুন" link to `/dating-live/<id>`; "এখন কেউ লাইভে নেই।" when empty, and a demo note when the backend is unreachable. Direct routes are guarded too: `/dating-live/:id`, `/dating-go-live` and `/call/dating/:id` show a status-aware blocked screen (pending / rejected with reason / no KYC) when not approved (no call starts, nothing is charged). Admin → users tab also shows the KYC status. **Demo KYC — no real government-database check; a verified KYC service is needed for real verification.** Previously verified (pre-review) users stay approved via the legacy `kycVerified` flag migration.
- **Dating Live (paid, per minute) — REAL live server:** inside the Dating page (after the 18+ gate) a "🔴 ডেটিং লাইভ" section lists live hosts and a "📹 লাইভে যান" button. **The live server is self-hosted in `server/index.js` — Express + `ws` WebSocket signalling on the same HTTP server/port (so it works on Railway's single PORT), no external service, no API keys.** REST: `GET /api/live` (live rooms), `POST /api/live` (create a room), `DELETE /api/live/:id` (end a room). WebSocket protocol (JSON, room = live room id): `join` {roomId, role: host/viewer, name}, `offer`/`answer`/`ice` relayed host↔viewer (viewer sends the offer, host answers — one RTCPeerConnection per viewer on the host side), `viewer-count` broadcast, `gift` broadcast, `chat` broadcast, `host-left` when the host disconnects. Frontend (`src/live.ts`): `fetchLiveRooms` / `createLiveRoom` / `endLiveRoom` / `connectLive` / `sendSignal`, WS URL derived from `VITE_API_URL` (https→wss). Watching a live → `/dating-live/<room-id>`: the viewer joins by WS, sends an offer, and receives the host's REAL camera stream into the video element. Going live → `/dating-go-live`: registers a room via `POST /api/live`, opens a WS as host, and answers each joining viewer's offer with the real camera tracks (front/back switch replaces the video track in every viewer connection). The Dating page shows real rooms from `GET /api/live` first (marked "আসল লাইভ", real viewer count, refresh button), with the 3 seed demo hosts below (marked "ডেমো") when the server is unreachable. When the server IS connected the screens show "🟢 লাইভ সার্ভার সংযুক্ত — আসল সম্প্রচার"; when not, they fall back gracefully to the old demo behaviour (own camera preview / simulated viewers) and say so — the app never crashes. **Limits (honest): STUN + free shared TURN** (`stun:stun.l.google.com:19302` + OpenRelay `turn:openrelay.metered.ca:80` / `turns:openrelay.metered.ca:443`, public test credentials `openrelayproject` — testing only, not production): some strict NATs / mobile networks may still fail to connect; a paid TURN is needed before real users. **Mesh:** the host sends one stream per viewer, so it works for a small audience (roughly 5–8 viewers); a big audience needs an SFU (e.g. LiveKit) later. Watching a live is prepaid at the admin-set **live rate** (`liveRate`, default **π ০.০৫/মিনিট** — separate from the dating call rate `datingRate`, default π ০.১/মিনিট; each has its own input + Save in Admin → Revenue, min π ০.০১/min, up to 2 decimals, saved to localStorage), only the viewer pays, live meter shows total paid with the split live, auto-cut when the viewer's balance runs out, end screen shows the full breakdown. **Revenue split is fixed: live host gets 70%, admin gets 30%.** **Live gifts (Pi only — ONE currency):** the watch screen has a gift shop — 🌹 গোলাপ ০.১ π, ❤️ হার্ট ০.২৫ π, 🎁 গিফট বক্স ০.৫ π, 💎 ডায়মন্ড ১ π. Sending a gift deducts Pi, shows the gift on screen and broadcasts it to the host over the live socket, and adds its value to the host's earnings at the same 70/30 split; not enough Pi shows "Pi ব্যালেন্স যথেষ্ট নয় — Pi ওয়ালেটে Pi যোগ করুন" with a button to the wallet. Pi is bought in the wallet (π Pi কিনুন — ১/৫/১০ π, টাকার ব্যালেন্স থেকে, ডেমো দর ৳১০০ = ১ Pi, অ্যাডমিন-নির্ধারিত). No external gift purchase, no free gifts. Recording is the same red-dot admin-only rule.
- **1-to-1 calls (REAL, call-by-link) — WebRTC peer-to-peer over the same self-hosted Railway server:** the caller starts from any `/call/<type>/<id>` page (expert / friend / dating — prepaid check, rates, first-call first-1-minute-free and caller-pays-for-dating all unchanged) and gets a short call code + a shareable link `https://picallbd.web.app/call/<code>`; the callee opens the link after login and sees a WhatsApp-style incoming-call prompt (✅ ধরুন / ❌ কাটুন) with the caller's name, and the call connects peer-to-peer (caller creates the offer, callee answers, remote stream renders in the main video, self-view stays small). The timer and billing start only when the peer connects — waiting costs nothing; the callee never pays. Camera front/back switch replaces the video track in the peer connection too; in-call chat is relayed over the call socket (contact ban still applies). If the peer never joins, the caller sees the waiting screen with the link + a cancel button; if the connection fails, a clear Bangla error is shown — a call is never faked as connected. Server (`server/index.js`): in-memory call rooms (`call-<code>`, max 2 peers), `GET /api/call/:code` (caller name / 404), WS `call-join` / `call-offer` / `call-answer` / `call-ice` / `call-chat` / `call-end` + `peer-joined` / `peer-left` / `call-ended`; live-room protocol untouched. Frontend (`src/call.ts` + `CallPage` in `src/pages.tsx`): `makeCallCode` / `callLink` / `fetchCallInfo` / `connectCall` / `createCallPeerConnection`, ICE = STUN + free shared TURN (OpenRelay, public test credentials — testing only). **Limits (honest): call-by-link until a real user directory/presence exists; free shared TURN is testing-grade — a paid TURN is needed for production; no real two-phone test done yet.**
- Affiliate commission (10%) only after the referred user's **first deposit AND first purchase** — never on signup/clicks alone. Referral is 2-tier (1.0 / 0.5 points, 1 point = ৳50).

## Firestore — real shared data (localStorage is the offline cache)

- **Model:** `users/{uid}` — one doc per Firebase Auth user (wallet, Pi ledger, call history, friends/requests, streak/daily bonus, referral, live earnings, KYC safe subset); `config/public` — one shared doc (admin rates + payment details, admin writes, everyone reads); `topups/{requestId}` — one doc per manual top-up request (user writes own, admin reads/approves).
- **Graceful degradation:** Firestore is NOT enabled in the console yet. Until it is, the app works exactly as before on localStorage. When Firestore is unreachable, every Firestore call returns null/false and the app stays on localStorage — nothing breaks. Firestore sync activates only for Firebase-authenticated sessions (Google / email-link login); email-OTP logins have no Firebase session, so they stay on localStorage.
- **Migration:** on first login with a Firebase UID, if no `users/{uid}` doc exists, the current localStorage state is written to Firestore once (no data loss, no invented values). After that, Firestore is the source of truth and localStorage is the write-through offline cache (800 ms debounce). If a different user logs in on a device that holds another user's cache, the syncable state resets to fresh-device defaults first (no cross-user leak).
- **Never synced to Firestore:** full NID number (`idNumber`), KYC selfie, KYC live video (stay local-only until a verified encrypted KYC service exists); admin SMS API key + SMTP password/user (stay on the admin's device + Railway server memory); dark mode, chat messages, transient notices.
- **Still to do (not in this change):** enable Firestore in the console (below), deploy the rules, then the cross-device admin KYC review queue and cross-device top-up crediting (today, approving a top-up credits the balance on the admin's own device — the demo behaviour — and the status syncs; real crediting needs a backend/Cloud Function).
- **Enable + deploy rules (after the console step):**
  1. Firebase console → Build → Firestore Database → Create database → **Native mode** → location **asia-south1** → **Production mode** (rules deny all until `firestore.rules` is deployed).
  2. `firebase deploy --only firestore:rules --project picall-76185` (rules live in `firestore.rules`, referenced from `firebase.json`).

## Viral growth (all five, built together)
- **Referral + invite link:** Feed and Wallet have a "বন্ধুকে ডাকুন" card with a personal link `https://picallbd.web.app/?ref=<code>` (copy + native share). A friend arriving via the link gets 10 π welcome bonus once; when that friend makes their first top-up, the inviter earns 20 π (tracked with a pending-referrer record). The existing points/affiliate system is untouched. Demo: referral tracking is per-device (localStorage); real cross-device tracking needs the backend.
- **Shareable clips:** every reel has a Share button (native share, clipboard fallback) with a per-reel share count; Go Live and live-watch end screens have a "📤 শেয়ার করুন" button. Total shares are tracked in the store and shown on the Reels page.
- **Daily bonus + streak:** Feed top card. 7-day ladder rising step by step: Day 1: 0.0001, Day 2: 0.00025, Day 3: 0.0004, Day 4: 0.00055, Day 5: 0.0007, Day 6: 0.00085, Day 7: 0.001 π, then the cycle restarts at Day 1. Missing a day resets the streak to Day 1. Claimable once per day. **30-day gift box (random draw):** 30 consecutive daily claims unlock a 🎁 gift box on top of the daily bonus — a random draw at claim time: the top prize is 1 π, everyone else gets a random consolation prize of 0.0001 / 0.00025 / 0.0005 / 0.001 π. After claiming, the 30-day counter restarts for the next cycle; missing a day resets the 30-day progress too.
- **Live gift leaderboard:** Feed section "🏆 সপ্তাহের লিডারবোর্ড" — top live hosts by gifts and top gift-givers, seeded with clearly-marked demo data, merged with the user's own live earnings / gifts sent on this device. Weekly (current week label).
- **Free-minute share link:** the invite card advertises "প্রথম কলের প্রথম ১ মিনিট ফ্রি + ১০ π" for friends arriving via the link; the existing first-call-first-1-minute-free rule is unchanged.

## Pi (π) — one currency, calls/live/gifts/top-ups
- **ONE currency: Pi.** The old generic coin system is gone — `coins` balance became the Pi balance (old stored value kept 1:1). Every price in the app is in Pi: dating call **π ০.১/মিনিট**, friend call **π ০.১/মিনিট**, live watch **π ০.০৫/মিনিট** (half the call rate), expert calls = taka rate ÷ 100 in Pi (৳১৫→০.১৫, ৳২৫→০.২৫, ৳১০→০.১). Call/live billing deducts from the Pi balance (prepaid, auto-cut); pre-call/pre-watch screens show Pi balance, Pi rate and talkable minutes; call history records rate/cost in Pi. First-call first-1-minute-free is unchanged. 70/30 live split is unchanged, now in Pi.
- **Pi wallet (Wallet → π Pi ওয়ালেট):** demo Pi wallet connect (generates a demo address starting with 'G'), Pi-buy from BDT balance at the admin-set rate (default **৳১০০ = ১ Pi**), demo add-Pi 0.1/0.5/1 for testing, Pi deposit (fixed demo deposit address + amount + tx/memo ref → credited immediately as "ডেমো জমা", with history) and Pi withdraw (own Pi address + amount; address must start with 'G' and be 56 chars; status "⏳ প্রক্রিয়াধীন (ডেমো)", with history incl. fee/received).
- **Withdraw minimum = 10 USDT worth of Pi**, computed from the admin rates: 10 × USDT-rate ÷ Pi-rate = **12 π at defaults** (১ Pi = ৳১০০, ১ USDT = ৳১২০). **Withdraw fee in Pi:** default 1% of the amount, minimum ০.১ π (e.g. 12 π → 0.12 π fee, receive 11.88 π), shown before confirming. Fee applies only to Pi withdrawals.
- **Admin-set rates (Admin → Revenue → π Pi দর):** `piRateBDT` (৳/Pi, default ১০০) and `usdtRateBDT` (৳/USDT, default ১২০), each with its own input + Save; `piWithdrawFeePct` (default ১%, ০–১০%) next to them. Changing them immediately changes the Pi-buy price and the withdrawal minimum in the Wallet. Expert Pi rates are derived from taka ÷ 100, not from these.
- **Manual top-ups (Wallet):** bKash, Nagad, Rocket, USDT and Binance Pay are all MANUAL (Bank removed 2026-11-20 — it did not work; there is no instant top-up any more). Each shows its demo receiving number/address/ID (clearly labelled ডেমো, with Copy) and step-by-step instructions; submitting a reference creates a PENDING top-up (localStorage) — the Wallet shows "⏳ টপ-আপ পর্যালোচনাধীন". **USDT offers 2 networks (TRC20 removed):** BEP20 (BNB Smart Chain — marked সবচেয়ে কম খরচ, fee hint ~০.০১ USDT), ERC20 (Ethereum, ~০.৬ USDT). Each network has its own demo address (both start with '0x') plus the warning to send only on the chosen network. The pending record stores the network; Admin sees it. **Binance Pay** shows a demo Binance Pay ID. USDT amounts are in USDT and credit the BDT balance at the admin-set USDT rate on approval (conversion shown, e.g. "10 USDT → ৳১,২০০").
- **Admin approval (Admin → Revenue → টপ-আপ অনুমোদন):** lists pending manual top-ups (method, network, amount + currency, reference, date) with ✅ অনুমোদন করুন (credits BDT balance; USDT converted at the admin-set rate) and ❌ বাতিল করুন.
- **π Pi রিপোর্ট (Wallet → 📊 π Pi রিপোর্ট):** every Pi movement in one ledger, newest first — date, type (জমা / তোলা / ডেইলি বোনাস / গিফট বক্স / রেফারেল / লাইভ আয় / গিফট দেওয়া / কল খরচ / লাইভ দেখা / Pi কেনা / বুস্ট / সুপার লাইক / ডেমো Pi), signed amount in Pi (+ green income, − red expense) and the running balance after each row. Summary at the top: মোট জমা, মোট তোলা, মোট আয় (বোনাস+রেফারেল+লাইভ আয়+গিফট বক্স), মোট খরচ (কল+লাইভ+গিফট), বর্তমান Pi ব্যালেন্স. The ledger is persisted in localStorage; new Pi movements are recorded going forward, and on first run it is built from the stored records (deposits, withdrawals, call history, live earnings, gifts sent, referral Pi) plus one 'সমন্বয়' line so the rows add up to the current balance — no amount is invented. Host live earnings (70% share) are now credited to the Pi balance too, so they can be withdrawn.
- **Demo honesty:** Pi balance, Pi deposit/withdraw, manual top-up numbers/addresses/IDs and USDT/Binance Pay details are DEMO placeholders — real Pi payments need the official Pi SDK + Pi app approval; real USDT/Binance Pay needs real receiving addresses set by the admin. No seed/private key is ever asked for or stored.
